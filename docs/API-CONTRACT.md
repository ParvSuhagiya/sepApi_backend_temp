# EarnRadar API contract (derived from code)

Source of truth for shapes: `docs/openapi.json` (generated by
`backend/scripts/export_openapi.py`; CI fails when it is stale). Field
limits below come from `backend/app/schemas.py`,
`backend/app/modes/customers/schemas.py` and `backend/app/config.py`;
error codes from `backend/app/errors.py`; behaviour from
`backend/app/main.py`. Do not guess — regenerate.

## Endpoints

### GET /api/health — public, minimal

- `200 {"ok": true, "version": "1.0.0"}` (no auth).
- `GET /api/health?detail=1` adds cache/lifetime/AI/budget counters, but is
  access-gated: with `ACCESS_CODE` set it requires `X-Access-Code`; with no
  code configured it is refused in production and open otherwise. The
  frontend does not use it.

### POST /api/search — income mode

Body `Profile`: `skills` string 2–300, `city` string 2–80, `hours` int
1–168 (default 10), `budget` int ≥ 0 (default 0).

Response `SearchResponse`:

- `opportunities[]` (up to 5; fewer possible with
  `meta.notes: ["fewer_than_5_opportunities"]`): `title`, `type`
  (`job` | `freelance` | `local business` | `online selling` | `content`),
  `why`, `income_estimate` (always an estimate), `demand`, `competition`,
  `fit`, `cost_ease`, `trust` (0–100 ints),
  `evidence[2..3]`, `plan_7_days` (exactly 7),
  `earn_score` (0–100), `score_breakdown` (floats),
  `adjustments[]` (human-readable guardrail notes).
- `jobs[]`: `title`, `company`, `location`, `via`, `salary|null`, `desc`,
  `link|null`, `flags[]`, `risk` (`Low`|`Medium`|`High`; rule-based
  text-pattern signal, never a safety verdict), `lat|null`, `lng|null`,
  `geo_precision` (`city`|`approximate`|null; absent when geocoding is off
  or the location is remote/unresolvable).
- `local[]`: `name`, `rating|null`, `reviews|null`, `phone|null`,
  `address|null`, `type|null`, `lat|null`, `lng|null` (from SerpAPI
  `gps_coordinates`, validated ranges, else null).
- `trend[]`: `{date, value}`; `trend_keyword|null`;
  `trend_growth` (`{keyword: int percent}`).
- `forum[]`: `{title, link, snippet}`.
- `stats`: `{credits_used, cache_hits}` (a repeat identical search reports
  `credits_used: 0`).
- `meta`: `{request_id, duration_ms, degraded[], partial[], notes[],
  city_center: {lat, lng}|null}` (geocoded profile city when
  `GEOCODE_ENABLED`, else null).

### POST /api/outreach — message drafts (never auto-sent)

Body `{profile, target}` where `target` is a dict of ≤ 2048 JSON chars.
Allow-listed target keys: `name`, `type`, `address`, `rating` (phone is
never sent). Customer-mode targets add `product_summary` (non-empty,
≤ 200 chars after stripping, else 422).

Response `{message (≤ 70 words, plain text), safety_note:
"Verify the business before paying or sharing documents."}`.

### POST /api/leads — customer-finder mode

Body: `offer` string 20–1000 (control chars stripped, rejected when > 30%
non-letters), `city` string 2–80, `monthly_price` int 0–1,000,000
(optional), `max_leads` int 5–20 (default 10).

Response `{schema_version: "1.0", offer_summary, leads[], market_notes[≤5],
meta, disclaimer}`. Each lead: `name`, `address?`, `rating?`,
`user_ratings_total?`, `business_type?`, `match_score` 0–100,
`match_reasons[1..3]`, `research_notes?`, `why_fit?`, `pitch_angle?`,
`suggested_first_question?`, `phone?`, `maps_url?`, `price_level?`,
`score_breakdown{}`, `likely_has_software`, `adjustments[]`.
`meta`: `{credits_used, cache_hits, degraded[], partial[], notes[],
timings_ms{}}`. Disclaimer: "Lead scores are signals from public data, not
guarantees. Verify details before contacting."

Deadline (`LEADS_REQUEST_DEADLINE_SECONDS`, default 45): on expiry, HTTP 200
with finished stages and `meta.notes: ["deadline_reached"]` when ≥ 1 lead
exists, else 502. Returns 404 `feature_disabled` when
`ENABLE_CUSTOMER_MODE=false`.

## Limits and headers

- Body cap 20 KB (413; chunked uploads measured on the stream).
- Per-IP rate limits per hour: search 10 (`RATE_LIMIT_SEARCH_PER_HOUR`),
  outreach 30, leads 5 (separate buckets; validation runs before limiting,
  so 422s never consume quota).
- Daily budgets (UTC, `0` = unlimited): SerpAPI 300, LLM 500, leads
  SerpAPI sub-budget 150.
- Server timeouts: search 90 s; leads deadline 45 s.
- Geocoding (off by default): ≤ 8 unique city/region strings per request,
  ≤ 1 upstream request/second, 30-day cache.
- Request headers: `Content-Type: application/json`,
  `X-Access-Code` (only when `ACCESS_CODE` is set; a soft gate, not a
  secret). Response headers: `X-Request-ID` on every response,
  `Retry-After` (seconds) on every 429. CORS allows `GET, POST, OPTIONS`
  with `Content-Type, X-Access-Code` headers.

## Errors

Always `{"error": {"code", "message", "request_id"}}`:

| Code | Status | Meaning |
|---|---|---|
| `invalid_input` | 422 | Validation failed (`"Invalid request: <fields>."`); also 413 `"Request body too large."` |
| `unauthorized` | 401 | Missing/wrong access code |
| `rate_limited` | 429 | Per-IP hourly limit (`Retry-After` set) |
| `budget_exhausted` | 429 | Daily budget spent with nothing servable (`Retry-After` set) |
| `upstream_failure` | 502 | SerpAPI/LLM failure, all sources failed, or deadline with zero leads |
| `ranking_failed` | 502 | No rankable opportunities |
| `feature_disabled` | 404 | Customer mode switched off |
| `internal` | 500 | Unexpected failure (safe message, CORS + request-id headers preserved) |
